# Physical AI 仿真任务结束后，Agent 希望获得的信息

## 1. 任务结果（最高优先级）
- **成功 / 失败 / 部分完成**：要有明确判定，不能只给一句"任务结束"
- **判定依据**：用的是哪条成功条件（如"目标物体位姿误差 < 2cm 且静止 0.5s"）
- **失败类型**：碰撞、超时、目标不可达、规划失败、控制发散、违反约束、感知丢失
- **失败时刻与位置**：仿真时间戳、机器人位姿、在任务流程的第几步

## 2. 量化指标
| 类别 | 指标 |
|---|---|
| 精度 | 末端/底盘位姿误差、轨迹跟踪误差 (RMS / max) |
| 效率 | 总耗时、路径长度、规划耗时、重规划次数 |
| 安全 | 最小障碍距离、碰撞次数与接触力峰值、约束违反次数 |
| 平滑性 | 速度/加速度/jerk 峰值，力矩是否饱和 |
| 资源 | 控制循环频率是否达标、每步计算延迟 |

每个指标最好附上**阈值或基线**，否则数值本身没有意义。

## 3. 时序数据（用于诊断）
- 状态轨迹：关节位置/速度/力矩、底盘位姿
- 控制指令 vs 实际执行（以便区分规划问题和控制问题）
- 规划器输出：全局路径、局部轨迹、每次重规划的原因
- 关键事件日志，带时间戳：`t=3.21s 检测到障碍 → 触发重规划`
- 格式：结构化（JSON / MCAP / rosbag），可按时间段查询，不要只给原始大文件

## 4. 感知与世界状态
- **Ground truth vs 感知结果**的对比：哪些物体漏检、误检，定位误差多大
- 场景快照：关键时刻（开始、失败、结束）的物体位姿
- 可选：关键帧图像或俯视渲染图，让我能"看到"发生了什么

## 5. 自然语言指令的理解反馈（若使用 NL 下达任务）
- 系统如何**解析**我的指令：识别出的目标、约束、子任务分解
- 歧义点及采用的解释（"放在桌子上" → 选了哪张桌子、什么位置）
- 无法执行的部分及原因

## 6. 因果分析 / 根因提示
- 系统自己的初步归因："失败源于第 2 次抓取时夹爪力不足，物体滑落"
- 每个子模块（感知 / 规划 / 控制）的健康状态
- 与上一次运行或基线的**差异对比**（回归测试场景尤其重要）

## 7. 可复现性
- 随机种子、场景配置、模型/代码版本、参数快照
- 一键重放（replay）到任意时间点的能力
- 支持从某个中间状态重新开始（checkpoint），不用每次从头跑

## 8. 可操作的下一步
- 可调参数及其当前值、合理范围
- 支持的操作接口：重跑、改参数、换场景、注入扰动
- 不确定性说明：仿真与真实的已知差距（摩擦、延迟、传感器噪声模型）

## 核心原则
1. **结论在前，细节可查**：先给判定和摘要，原始数据按需获取
2. **结构化优于自由文本**：agent 要能直接解析和比较
3. **能区分故障层级**：感知、规划、控制、环境，各自的问题要分得开
4. **可对比、可复现**：没有基线和种子，结果就没法用于迭代
