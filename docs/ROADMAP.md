# DreamBench 实施路线与验收清单

目标是把一次 Dream‑1 指令或执行参数改动变成可复跑、可核查的仿真对照。第一版交付本地 Web 配置、Python 执行和报告回放。已有的苹果入碗实验用来验证这条链路。详细赛题和扩展实验见[指导方案](../Dream-1_回归测试台_指导方案.md)。

## 1 确认本地基线并保存可复现版本

- [x] 用默认 YAM 桌面跑通真实的苹果入碗 A/B。48 步失败，24 步成功。本例只有一对试验，结论为建议复测。
- [x] 接通三路视频、轨迹、接触状态、可选 YOLO 和 Web 回放。
- [x] Web 可以导出实验 JSON。CLI 的指令对照流程已用模拟运行验证。
- [ ] 在本地运行 `python3 -m unittest discover -s tests -v`，再启动 Web，核对已有实验和回放。
- [ ] 将 Web 文件、JSON 执行入口和文档整理到同一个 PR。用干净检出验证页面能打开并导出配置，再加载已有实验目录验证回放。

验收标准。从同一个 Git 版本能独立复现并启动页面，识别已完成的功能和待接入的草稿。API 凭据、模型权重和原始录制保存在本地。Git 提交源代码、文档、经确认可分享的实验配置和摘要。

按顺序完成。每次只推进一个验收点。若时间有限，优先完成第 1 至 3 步，并缓存真实报告用于演示。

## 2 拆出场景与判分器

- [ ] 把默认桌面和一个可重复的苹果偏移布局分别注册为两个场景 ID。先沿用 YAM 的机器人和三路相机接口。
- [ ] 把现有苹果入碗规则从运行入口提取到单独的判分模块，并通过任务 ID 选择它。保留成功、仍被夹持、卡在碗沿和掉出等核对样例。
- [ ] 先定义配置字段和回传数据。场景解释如何加载、复位和读取初始状态。判分器声明成功条件，并返回结果、理由和证据时刻。执行器只依赖这些接口。

验收标准。默认布局的已有录像仍能用原有判分规则复核。新布局能从同一配置复位两次，苹果和碗的起始位置一致。Web 中只有已经接通的场景和任务组合可以进入执行流程。

## 3 做成多场景回归并汇总报告

- [ ] 在实验配置里增加场景列表。由执行器为每个场景运行同一对基线和候选，保存场景 ID、初始状态或种子、实际指令、动作上限、时限和版本信息。
- [ ] 第一组验收只需要默认布局和偏移布局各跑 A、B，共四轮。每次实验只改变 prompt 或动作上限中的一个。
- [ ] 报告按场景列出结果、请求次数、耗时、回放链接和判定时刻。任务失败、超时、API 错误和仿真错误各有状态。未完成的轮次也要有记录。
- [ ] 用回放人工核对一条成功和一条失败。若任一布局 A/B 起点不同，将该对标为证据不足。

验收标准。一个配置能生成四条可追溯的真实记录。Web 报告可以打开任一轮回放，且清楚区分样本数量、成功率和异常。四轮用于验收工具。稳定性结论依赖更大的配对样本。

## 4 接入网页启动

- [ ] 配置页提交已校验的实验快照，复用 Python 执行器。先支持一次一个实验，显示运行阶段和最终结果。
- [ ] 本地 Web 页面在用户确认启动后才发起会消耗 Dream‑1 额度的运行。先用模拟执行验证开始、完成和错误状态。
- [ ] 完成后提供新报告入口，展示实际运行的两份配置和逐轮证据。

验收标准。用户能从浏览器配置、启动并查看同一次实验。现有 CLI 仍可用于复现同一份配置。

## 5 验证第二个任务并准备演示

- [ ] 先用现有桌面上的香蕉上盘验证第二个判分器。为场景适配的泛化仍保留默认和偏移布局两组证据。若要验证不同操作类型，再接入带滑轨的抽屉场景和开度判分器。
- [ ] 预先保存一份实测报告、可播放证据和备用录屏。现场展示配置差异、切换场景以及打开失败回放。将单对结果称为观察，复测后再下结论。
- [ ] 有余力再增加配对样本、置信区间、请求延迟或动作平滑度。安全指标需要定义事件规则并用相应日志核对。最后接自然语言配置、搜参和自动重试。

三分钟演示顺序。30 秒讲用户问题，90 秒展示配置与已实跑报告，60 秒打开证据并解释是否值得复测。评委需要记住的是如何验证一次改动，以及如何看见证据。
